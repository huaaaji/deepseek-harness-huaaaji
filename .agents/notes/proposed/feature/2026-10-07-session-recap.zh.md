# Agent Note: 会话回顾——用户离开期间发生了什么的一份持久记述

Status: proposed

[English](2026-10-07-session-recap.md) | 中文

## 问题

用户不在时，DSH 会话仍在继续工作：回合不断完成，后台作业结束，子代理与工作流结算，transcript 持续增长。当用户回来时——无论是回到 Web 客户端里仍然打开的会话，还是从会话目录恢复一个会话——能看到的只有状态点和滚动位置，因此要弄清发生了什么只能自己读一遍，而这段阅读的长度随会话增长。

Claude Code 已经提供了终端尺度的这一功能。它的 session recap（[v2.1.114](https://code.claude.com/docs/en/whats-new/2026-w17)、[`/recap`](https://code.claude.com/docs/en/interactive-mode)）会在用户切回一个无人看管的终端时显示一行模型写出的文字。终端失焦且距上一次回合完成至少三分钟后，它在后台生成；会话至少满三个回合后才可能出现；不会连续出现两次；长度上限 400 字符；默认开启并可在 `/config` 关闭；非交互模式永不运行；来自转发消息或自动化提示的请求会被拒绝，只有用户自己发起的才执行。

这些机制 DSH 都已经具备，缺的只是功能本身。[`dsh-session-title`](../../../packages/session/session-title/README.md) 已经在 agent 循环之外对会话历史发起辅助模型调用，记录精确的请求，把接受的结果持久化为仅写入日志的事件，用新修订取代旧工作，并通过会话投射把结果交给客户端。`dsh-compaction` 已经会为历史生成摘要，并把结果显示为 transcript 标记。没有任何机制产出一份面向用户的、关于某一段已完成工作的记述，也没有任何机制在空闲时安排工作。

## 提案

新增一个按 session-title 家族组织的会话回顾能力家族，并按 compaction 标记的方式新增一行 transcript。

### 事件与能力缝

`@deepseek-ai/dsh-session-recap` 定义 `ctx.sessionRecap` 与两个仅写入日志的 `SessionEventMap` 成员：

- `session/recap`——一条被接受的回顾：文本、来源（`provider`，含 provider id 与实际使用的模型路由）、覆盖范围（首个与末个被覆盖的表面 seq，以及被覆盖的回合号），以及生成器实际看到的 `user/message` 与 `assistant/message` seq。
- `session/recap-llm-request`——一次派发前记录的精确模型可见请求：路由、系统提示、消息、输出 token 上限与来源 seq，对齐 `session/title-llm-request`。

两个事件都不是表面事件，都不进入任何模型请求，也不扩展 `SurfaceEventType`。服务本身负责接受：校验返回的 seq 集合来自该次请求快照、归一化文本、强制字节上限，然后追加事件。`foldSessionRecap(events)` 是纯折叠函数，`get(session)` 返回最近一条被接受的快照。该服务注册一个客户端可见的 `recap` 投射单元来承载这份快照，使会话目录行与冷会话无需加载历史窗口即可读取最近一次回顾。

不提供确定性兜底。程序不借助模型就能从日志拼出的回顾并不是回顾，回合计数也不是对工作的记述。没有注册 provider 时，`/recap` 报告未配置回顾生成器。

### 生成

`@deepseek-ai/dsh-session-recap-llm` 承载共享生成策略，对齐 [`dsh-session-title-llm`](../../../packages/session/session-title-llm/README.md)：校验配置，在记录或派发之前按 `maxInputBytes` 度量最终 JSON 封装后的提示而非截断，在消费流期间与流结束后都重新检查时限与调用方取消，拒绝空、畸形或非文本输出，并在调用 `ctx.llm.stream()` 之前记录请求。除非以 `provider`/`model` 成对覆盖，路由取当前会话已记录的 `request/header` 路由。

输入是自上一次被接受回顾以来窗口的有界摘要，而不是整段历史：完整的人类提示、每个回合的最终助手文本、每个工具调用的名字与有界的结果预览，以及作业、子代理与工作流的完成通知。选择器取能放进 `maxInputBytes` 的靠后事件，并始终带上窗口的首个人类提示，因此摘要是日志的确定性函数，成本由配置而非会话长度决定。输出只有一行：非 CJK 文本按 `targetWords`，CJK 按 `targetCjkCharacters`，并由 `maxBytes` 封顶。

### 触发

`@deepseek-ai/dsh-session-recap-idle-llm` 注册 provider 并负责自动节奏。它在回合结束时启动计时器、在回合开始时清除计时器，并在计时器触发且会话空闲（无运行中的回合、无排队输入）、已完成回合数不少于 `minTurns`、且自上次被接受回顾以来至少完成了一个回合时生成。“不连续两次”这条规则因此是从日志读出的，而不是保存在客户端状态里。释放会清除计时器并中止进行中的生成；迟到的结果无法覆盖更新的结果。

按需生成由 `@deepseek-ai/dsh-command-recap` 提供：一个注册在 `ctx.commands` 上的 `/recap` 命令，调用该服务并像 `/compact` 那样报告各类预期失败。命令只能通过调用它的交互式适配器到达 agent，因此例程、webhook、定时提示或程序驱动的回合都无法请求回顾，回顾也刻意不作为模型工具暴露。

### 客户端呈现

`ui-chat` 新增 `recap` 会话节点与 `RecapItem` 行，跟随 compaction 标记的做法：节点定义从 `session/recap` 事件派生，渲染器注册到 `conversation.chat.node`，`/recap` 的命令结算折叠进该行，使同一次回顾不会渲染两次。该行显示生成的句子与被覆盖的回合数，可展开查看覆盖范围，所有标签取自 locale 字典。

该行是持久的，位于它所覆盖的回合之后，而不是在用户回来时短暂浮出。DSH 会话会从目录恢复，且可同时运行多个，因此一行能在重新加载后保留、能用于几天后才打开的会话、且不需要客户端本地“已读”状态的实现，比短暂形式更有价值；位置本身已经传达了“这就是当时发生的事”。

### 持久化、路由与成本

两个事件都是增量的、仅写入日志的，且回放或继续会话都不需要它们，因此在使用允许时，实现会用信封的 `ignorable` 标记它们；否则遵循 session-title 的先例，按 required-on-read 发布并确认持久化类型变更。无论走哪条路，本变更都要重新生成持久化目录、更新 TypeScript 与 Python SDK 针对扩展后 `SessionEventMap` 的预期输出，并在旧构建将开始拒绝含回顾日志时补一条升级指南条目。

一次自动回顾在每个空闲时段只需一次有界的辅助调用。窗口有界、输出很短、生成以取代而非排队的方式处理，且中间必须至少完成一个回合；因此一个不再回来的用户每个空闲时段只付一次小调用，不会有更多。

### 打包方式

| 包 | 角色 | ctx key |
|---|---|---|
| `packages/session/session-recap` | 持久回顾状态、接受、折叠、投射 | `ctx.sessionRecap` |
| `packages/session/session-recap-llm` | 共享生成策略 | — |
| `packages/session/session-recap-idle-llm` | 基于共享策略的空闲节奏 provider | 注册 `ctx.sessionRecap` |
| `packages/session/command-recap` | 按需 `/recap` | 注册到 `ctx.commands` |
| `packages/client/ui-chat` | `recap` 会话节点与行 | `conversation.chat.node` |

随附的 `dsh` 与 `web` bundle 以显式上限挂载该能力缝与空闲 provider，使客户端能显示它的场景默认开启；`headless`、`sdk` 与 `acp` profile 都不挂载。每个上限都是带校验的 `Config` 字段，库里不给默认值，与 session-title 家族现有做法一致。

## 考虑过的替代方案

**只在回来时短暂浮出的浮层。** 这与 Claude Code 的呈现一致，但它需要客户端本地的“已读”状态、为自动触发新增一条浏览器可见性路径，而且对从目录重新打开的会话什么都显示不出来——而那恰恰是 DSH 会话的常见情形。如果持久行被实测证明会污染 transcript，再重新引入。

**聚焦时在客户端生成。** 触发更简单，但会把模型调用放到用户回来的关键路径上（切回来之后要等数秒），完全无法在后台生成，而且回顾只存在于某个浏览器里而不是会话日志里。否决。

**复用 `session/title`。** 标题是从人类提示派生、用于列表行的短标签；回顾记述的是一个窗口内助手与工具的工作，且在会话内部被阅读。让一个服务承载两种含义会合并两套节奏、两套长度策略与两套评审面。否决。

**复用 compaction 摘要。** compaction 摘要的存在意义是为模型替换历史，以数千 token 计，与表面替换和提示词缓存记账耦合，且只在出现压力后才存在。回顾面向用户、很短、从不替换任何东西，且必须在从不压缩的会话中也存在。否决。

**把回顾暴露为模型工具。** 模型因此可以请求回顾，但信任规则的存在正是为了不让自动化或转发的输入触发它，而且模型可见的回顾还会进入请求前缀与其缓存记账。否决。

**确定性兜底回顾。** 便宜，但它产出的是回合计数而不是对工作的记述；一条总是出现但很弱的回顾比诚实的缺席更糟。否决；`/recap` 报告未配置生成器。

**只做投射单元，不写会话事件。** 可以在宿主侧折叠并下发给客户端而不触碰日志。但回顾必须能在重新加载后存活、能被分离读取者看到、并能归因到产生它的确切输入，而这些日志本就提供。否决。

**按时间而非按上次回顾选择覆盖窗口。** 基于时间的窗口需要在日志里保存时钟状态，并会产生重叠与空档；自上次回顾以来的窗口恰好就是用户要问的问题，且仅凭日志即可推出。否决。

相关工作：[可回溯压缩](2026-07-06-recallable-compaction.zh.md)重新组织模型保留什么，其中“预步骤摊销草拟 stub”的后续事项是空闲期生成的模型侧对应物。[插件拥有的消息投射](../../implemented/architecture/2026-09-11-plugin-owned-message-projections.zh.md)管辖会改变内容的事件；回顾仅写入日志，不需要解释器。

## 验收标准

- 一个完成至少 `minTurns` 个回合后空闲 `minIdleMs` 的会话，恰好新增一条 `session/recap` 事件，带有覆盖范围与来源 seq；在没有新回合完成的第二个空闲时段不再新增。
- `/recap` 按需追加一条被接受的回顾，把各类预期失败报告为人类文本，且在未注册 provider 时不改变日志。
- `session/recap-llm-request` 能重现被派发的请求；超过 `maxInputBytes` 的请求被拒绝而不是截断；取消与时限到期都不会追加。
- 客户端每条被接受的回顾恰好渲染一行，标签由 locale 拥有，并折叠 `/recap` 结算而不是重复显示。
- `foldSessionRecap` 在回放中往返一致；`recap` 投射等于最近一条被接受快照；持久化目录、两份 SDK 预期输出与包 README（英文与中文）均为最新。
- 新源码达到逐文件 100% 覆盖；释放测试证明计时器与监听器被移除；一个真实组合的 Loader 测试启动空闲 provider 并观察到一条被追加的回顾。

## 风险

- **回顾错了重点**：摘要可能略去用户真正关心的细节。覆盖范围与请求记录使这种略去事后可查，输入选择器是日后放宽的唯一位置。
- **无人值守会话的空闲成本**：被例程拖着一直运行的会话会在每个空闲时段持续付费。输出上限、窗口边界与每空闲时段一次的约束限制了成本；若实测不成立，就把自动节奏限定在有客户端连接时。
- **持久行的噪音**：一行始终可见会改变那些从不想要回顾的用户的 transcript。配置开关可以关闭该功能，短暂浮层方案也仍然可用。
- **持久化类型增长**：再多两个事件类型会加宽格式，而 required-on-read 的选择会让旧构建拒绝含回顾的日志；升级指南条目会明确写出这一代价。
- **并发下的触发正确性**：在回合开始时触发的计时器不得生成或追加，被取代的调用不得落地。复用 session-title 的取代与取消模式可以收敛这一点，验收标准也将其钉住。
